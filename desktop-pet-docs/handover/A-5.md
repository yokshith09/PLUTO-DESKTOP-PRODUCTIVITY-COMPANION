# A-5 — "Your day with assistants" evening line (Antigravity, after A-2)

Branch `antigravity/a-5`, from `main` after A-2's PR exists (rebase onto it). **Do not start until A-2 is in place**: it needs the chat events A-2 stores. Read [README.md](README.md) first.

## What the owner wants (plain words)
One calm line in the evening, above the pet: **"Today with assistants: 5 chats finished, 2 asked for permission. Most in DESKTOP-PET."** It is a small thank-you and a summary, never a score.

## Build exactly this

**Pure logic (TypeScript)** — new file `src/features/assistants/dayLine.ts` with tests in `dayLine.test.ts`:
- `dayLine(events: {assistant:string; folder:string; kind:string; atMs:number}[], today: string /* yyyy-mm-dd, local */): string | null`.
- Only events whose local date equals `today` count (use `ymd` from `src/lib/dates.ts`). Counts: `done` events = chats finished; `permission` events = permission requests ("asked for permission"; **not** "answered", the app does not know). `needs` events are not counted.
- No finished and no permission events → `null` (say nothing).
- Text (exact): `Today with assistants: {d} {d==1?"chat":"chats"} finished` + (`, {p} asked for permission` if p>0) + `.` + (` Most in {folder}.` when at least one folder has strictly more finished chats than every other; ties → leave the sentence out). If only permission events exist: `Today with assistants: {p} asked for permission.`
- Words stay neutral and kind (no "only", "just", "failed"). Keep `src/lib/noGuilt.test.ts` passing.

**When it shows** — a hook in the main window, modelled on `useRoutineReminder` in `src/features/routine/useRoutine.ts` and `useRepeatReminder.ts`: a new `useDayWithAssistants()` called once from `src/App.tsx` next to `useRoutineReminder()`.
- Shows once per day, **between 17:30 and 21:30 local time**, the first time the check runs in that window (check on mount, on `onWake`, and with one timer to 17:30 like the routine reminder; no polling).
- Must go through the notification budget: `tryNudge("with-assistants", now, () => petSay({ text, pose: "wave", ms: 10_000 }))` (defined in `src/features/companion/useCompanion.ts`, which uses the budget in `src/lib/nudges.ts`; it returns `Promise<boolean>`, true when the callback ran). That already enforces quiet hours, the daily maximum and the gap; **do not bypass it**.
- Remember that it was shown today in a preference `ui.day_with_assistants` (a `yyyy-mm-dd` string) via `ipc.prefsGet` / `ipc.prefsSet`; show nothing if it equals today. Mark it shown only when `tryNudge` actually ran the callback (await `tryNudge`'s boolean).
- Events come from `ipc.devChatEvents` (added by A-2).

## Boundaries
- Allowed files: `src/features/assistants/dayLine.ts` + test (new), `src/features/assistants/useDayWithAssistants.ts` + test (new), one line in `src/App.tsx`, the report.
- No Rust changes, no new setting in the Settings page, no new page or tab, no dependency.

## Must not
- Must not claim "answered" permissions, hours worked, or any number the app does not know.
- Must not rank, score, compare with other days, or use streak/guilt wording.
- Must not show anything when there were no chats today.
- Must not run more than once a day, nor outside 17:30–21:30, nor bypass `tryNudge`.
- Must not read note, diary or task text.

## Acceptance
1. Pure tests for every text variant above (1 and many chats, with/without permission, tie vs clear winner, only permission, none → null, events of other days ignored).
2. Hook test with fake timers: shows once inside the window, not before 17:30, not after 21:30, not twice, not when `tryNudge` refuses (quiet hours, daily max), and records `ui.day_with_assistants` only when shown.
3. Unverified in the real pet window; say so.
