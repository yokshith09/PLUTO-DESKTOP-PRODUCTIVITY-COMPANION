# A-3 — "Finished while you were away" (Codex)

Branch `codex/a-3`. Read [README.md](README.md) first; its rules apply.

## What the owner wants (plain words)
If an assistant chat **finishes, needs you or asks permission while you are away from the computer**, the pet tells you **once, when you come back**: "Welcome back. Claude Code finished in DESKTOP-PET while you were away." No more than one bubble per return, never repeated.

## Build exactly this

**Meaning of "away".** No keyboard or mouse input for at least `pluto_core::usage::IDLE_THRESHOLD_MS` (10 minutes, already used by time tracking). Use `pluto_core::usage::effective_idle_ms(idle, screen_held)` so a film or call that holds the screen on does not count as away.

**Core (pure logic, no OS)** — new file `crates/pluto-core/src/mcp/away.rs`, declared in `mcp/mod.rs`:
- `struct Away` keeps the chats that spoke while you were away: `Vec<Missed { assistant, folder, kind: Finished | Needs | Permission, at_ms }>`, at most 10, one per assistant+folder (a newer word from the same chat replaces the older one; keep the strongest kind: Permission > Needs > Finished).
- `Away::note(&mut self, missed, idle_ms, now)` stores it **only if** `idle_ms >= IDLE_THRESHOLD_MS`.
- `Away::back(&mut self, idle_ms, now) -> Option<String>`: returns the bubble text and clears the list when `idle_ms < 3_000` (input has resumed) and the list is not empty; otherwise `None`. Entries older than 8 hours are dropped first.
- Text (exact):
  - one chat: `Welcome back. {assistant} finished in {folder} while you were away.` For `Needs`: `Welcome back. {assistant} needs you in {folder}.` For `Permission`: `Welcome back. {assistant} asked for permission in {folder}.` With no folder, drop ` in {folder}`.
  - two or more: `Welcome back. {n} chats spoke while you were away: {folder1}, {folder2}.` (list at most 3 folders, then ` and {k} more`; an empty folder shows the assistant name instead).
  - Use the bubble cleaner `clean_bubble` (same file `mcp/mod.rs`) on the result.

**Hook side** — in `crates/pluto-core/src/mcp/mod.rs`:
- Add `fn finished(..)` (signature below) to the `Host` trait **as a new method with a default empty body, placed in its own block with a comment `// A-3`**. Signature: `fn finished(&self, _assistant: String, _place: Option<String>, _kind: &'static str) {}` with `kind` one of `"done"`, `"needs"`, `"permission"` (the same shape A-2 uses for `chat_event`; keep the two methods separate).
- Call it from `react_once_at` for `agent_done`, `agent_needs_you`, `agent_permission` (next to the existing `host.waiting(...)` block; do not change that block's behaviour).

**Shell** — `src-tauri/src/mcp.rs` (`ShellHost`):
- Implement `finished`: read the current idle time (`crate::tracking::win::idle_ms()` on Windows, `crate::tracking::mac::idle_ms()` on macOS; other targets: treat as not idle) combined with `crate::tracking::win::display_required()` on Windows (false on macOS), pass it to `Away::note`. Keep the `Away` value in a new struct next to `WaitList`, behind a `Mutex`.
- A small background task (use `tauri::async_runtime::spawn`, the same way the file already spawns tasks) that **runs only while the list is non-empty**: every 5 seconds read idle time; when `Away::back` returns text, show it through the same path as other pet bubbles (`show_on_pet(&app, message, false)` using a `PetMessage { assistant: String::new()-safe value, text, reaction: None }` — read how `show` builds a `PetMessage` and follow it) and **respect the focus guard** (`self.guard.hold(&message)` exactly like `show_or_hold`). When the list becomes empty the task ends; start it again on the next `note`.
- Bubble has **no action** (no click behaviour) in this task.

## Boundaries
- Allowed files: `crates/pluto-core/src/mcp/away.rs` (new), `crates/pluto-core/src/mcp/mod.rs` (only the `Host` method, the call in `react_once_at`, the `mod away;` line), `crates/pluto-core/src/mcp/tests.rs` (tests), `src-tauri/src/mcp.rs` (the `ShellHost` part), the handover report. Nothing else.
- No UI/TypeScript changes at all. No new setting. No new dependency.

## Must not
- Must not change what happens when you are **not** away (no extra bubbles, no change to the badge, the waiting list or A-1/A-4 behaviour).
- Must not store anything on disk (the list lives in memory; a restart forgets it).
- Must not read idle time continuously when nothing is pending.
- Must not show the text of the chat's request (only assistant name and folder).
- Must not touch `waiting.rs`, `link.rs`, `hookctx.rs`, `setup.rs`.

## Acceptance
1. Finish while idle ≥ 10 min → one bubble at the first input afterwards; none if you were not away; never twice for the same return.
2. Two chats → one combined line. A newer word from the same chat replaces the older one.
3. During a focus session with the guard on, the bubble is held like other bubbles.
4. Entries older than 8 h are not announced.
5. Tests (pure): threshold, "back" threshold, replacement and strongest-kind rule, the exact texts including 2, 3 and 5 chats and empty folder, expiry, cap of 10. Plus one `ShellHost` level test only if it can be done without a window; otherwise say so in the report.
6. Unverified on a real PC (idle reading, bubble timing); say so in the report.
