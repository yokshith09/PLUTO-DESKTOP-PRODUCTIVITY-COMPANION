# A-2 — "Chats in Project Activity" (Antigravity)

Branch `antigravity/a-2`. Read [README.md](README.md) first; its rules apply.

## What the owner wants (plain words)
A project's **Activity** tab already lists "Committed", "Pushed", "Finished “task”" and "Edited the note …". It should also list **what your assistants did in that project's folder**: "Claude Code finished", "Claude Code needed you", "Claude Code asked for permission", with the time. No chat text.

## Build exactly this

**Core (pure)** — new file `crates/pluto-core/src/mcp/chat_events.rs`, declared in `mcp/mod.rs`, modelled on `GitEvent` / `events_from` / `remember` in `crates/pluto-core/src/devwatch.rs`:
- `#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)] #[serde(rename_all = "camelCase")] pub struct ChatEvent { pub assistant: String, pub folder: String, pub kind: String, pub at_ms: i64 }` with `kind` one of `done`, `needs`, `permission`. Do not derive `ts_rs`: `GitEvent` is hand-typed in TypeScript (`src/ipc/client.ts`, `export type GitEvent = …`), so add `export type ChatEvent = { assistant: string; folder: string; kind: "done" | "needs" | "permission"; atMs: number }` there and export it from `src/ipc/index.ts` the same way.
- `EVENTS_KEPT = 500`, `EVENTS_PREF = "dev.chat_events"`, `events_from(stored) -> Vec<ChatEvent>` (malformed entries dropped), `remember(&mut Vec<ChatEvent>, ChatEvent)` (newest first, truncated). **Collapse repeats:** if the newest stored event has the same assistant, folder and kind and is less than 60 seconds older, replace it instead of adding (hooks can fire twice).
- `folder` is the **last path segment only** (that is all the hook knows, e.g. `DESKTOP-PET`), taken from `waiting::from_place`.

**Hook side** — `crates/pluto-core/src/mcp/mod.rs`:
- Add `fn chat_event(&self, _assistant: String, _place: Option<String>, _kind: &'static str) {}` to the `Host` trait in its own block marked `// A-2` (default empty body).
- Call it from `react_once_at` for `agent_done` → `"done"`, `agent_needs_you` → `"needs"`, `agent_permission` → `"permission"`. Do not change the existing `host.waiting(...)` block's behaviour. Events with no folder are not stored.

**Shell** — `src-tauri/src/mcp.rs` (or a new small section next to `WaitList`; do **not** edit `devwatch.rs` beyond what is said here):
- Implement `ShellHost::chat_event`: load events from the `dev.chat_events` pref once (lazily), `remember`, write back with `SettingsService::set_pref` in a spawned task (same pattern as `save_activity`), then `app.emit("dev://chat", ())`.
- New Tauri command `dev_chat_events() -> Vec<ChatEvent>` registered in `src-tauri/src/lib.rs`; add `devChatEvents` to `src/ipc/client.ts` and `dev_chat_events: () => [...]` demo data to `src/ipc/mock.ts` (two or three sample events; copy the shape of `dev_git_events`).

**UI** — only the Activity list of a project:
- `src/features/projects/spaces.ts`: extend `activity(...)` with a new parameter `chats: { assistant: string; folder: string; kind: string; atMs: number }[]` **after** the existing ones (keep existing callers compiling with a default `[]`). Add `ActivityItem.kind` values `"chat-done" | "chat-needs" | "chat-permission"`. An event belongs to a project when `space.folder` is set and **the last path segment of `space.folder` equals `event.folder` case-insensitively** (use the existing `shortName` helper if it returns the last segment; check it). Texts (exact): `Claude Code finished` / `Claude Code needed you` / `Claude Code asked for permission` (use the event's assistant name).
- `src/features/projects/SpaceParts.tsx` (`ActivityPanel`) and `ProjectsPage.tsx` (`RecentActivity`): fetch `ipc.devChatEvents` with the same `useQuery` pattern and refetch interval as `devGitEvents`, pass to `activity`. Show each new kind with an icon from `lucide-react` already used in the file (pick similar ones: e.g. `Bot` for done, `Hand` for needs/permission); same row layout, no new component, no new colours.

## Boundaries
- Allowed files: `crates/pluto-core/src/mcp/chat_events.rs` (new), `mcp/mod.rs` (Host method, call, `mod`), `mcp/tests.rs`, `src-tauri/src/mcp.rs`, `src-tauri/src/lib.rs` (one line), `src/ipc/client.ts`, `src/ipc/index.ts` (one export), `src/ipc/mock.ts`, `src/features/projects/spaces.ts`, `SpaceParts.tsx`, `ProjectsPage.tsx`, their tests, the report.
- No new tab, page, setting, dependency or database migration (a preference is used, as git events do).

## Must not
- Must not store or show the chat's request text, transcript, tool name, or the full folder path.
- Must not change how commits, pushes, tasks or notes appear in Activity.
- Must not change the waiting badge, A-1, A-4, or the pet's bubbles.
- Must not match projects to chats by anything other than the folder's last segment (and say in the report that two folders with the same name collide: a known limit).
- Must not add anything to the Overview, Today or Time pages.

## Acceptance
1. A hook "done" from folder `DESKTOP-PET` shows "Claude Code finished" in the Activity of the project whose folder ends in `DESKTOP-PET`, with the time; other projects do not show it.
2. Needs and permission show their own lines; newest first among all kinds; the 50-item cap still holds.
3. Events survive a restart (pref); at most 500 kept; a repeat within 60 s collapses.
4. Core tests: `events_from` junk handling, `remember` order/cap/collapse; a `react_once_at` test (see how `FakeHost` in `mcp/tests.rs` records waits) proving the three reactions call `chat_event` with the right kind and `agent_resumed`/`agent_error` do not.
5. UI tests: `spaces.test.ts` for matching (case-insensitive, last segment, project with no folder, other project) and texts; one component test that the Activity list shows the new rows.
6. Unverified in the real window and with real hooks.
