# A-7 — "Still working" notice (Codex, after A-3)

Branch `codex/a-7`, started from `main` after A-3's PR exists (rebase onto it if it has merged; if not, branch from `main` and expect a trivial conflict in the `Host` trait: keep both methods). Read [README.md](README.md) first.

## What the owner wants (plain words)
So you know a long chat is not stuck, the pet says **"Claude Code has been working 25 min · DESKTOP-PET"** once a chat has been working that long without finishing or needing you.

## Build exactly this

**What "working" means.** From the moment you send a prompt (the silent `agent_resumed` reaction, sent by Claude Code's `UserPromptSubmit` hook) until the same chat sends `agent_done`, `agent_needs_you`, `agent_permission` or `agent_error`. A chat is one assistant + folder (same key as `waiting.rs`).

**Core (pure)** — new file `crates/pluto-core/src/mcp/working.rs`, declared in `mcp/mod.rs`:
- `struct Working` with `start(assistant, folder, now_ms)`, `end(assistant, folder) -> bool`, and `due(now_ms) -> Vec<Notice { assistant, folder, minutes }>`.
- Thresholds (constants): notify at **25 minutes** and once more at **60 minutes** of one run; never more than those two per run. Expire a run silently after **3 hours** (the chat was probably closed; no hook says so). At most 20 runs kept (oldest dropped).
- `due` returns each notice once (remember which thresholds were announced per run). A new `start` for the same chat begins a fresh run.
- Text (exact): `{assistant} has been working {minutes} min · {folder}`; with no folder: `{assistant} has been working {minutes} min`. For the 60-minute notice the same format with `60`. Use `clean_bubble`.

**Hook side** — `crates/pluto-core/src/mcp/mod.rs`:
- Add `fn working(&self, _change: WorkChange) {}` to `Host` as its own block marked `// A-7` (default empty), and a small `pub enum WorkChange { Start { assistant: String, place: Option<String> }, End { assistant: String, place: Option<String> } }`.
- In `react_once_at`: `agent_resumed` → `Start` (this branch already returns early after the waiting bookkeeping; add the call before that return); `agent_done`, `agent_needs_you`, `agent_permission`, `agent_error` → `End`. Do not change anything else in that function.

**Shell** — `src-tauri/src/mcp.rs`:
- A `WorkList` (like `WaitList`) holding `Working` behind a `Mutex`; `ShellHost::working` applies the change, using `waiting::from_place` to get the folder from the place text.
- One background loop **started only while at least one run exists**, waking every 60 seconds, calling `due(now)` and showing each notice as a pet bubble (same path as A-3: `show_on_pet(&app, message, false)` with `reaction: None`, and the focus guard's `hold` respected). The loop ends when the list is empty.

## Boundaries
- Allowed files: `crates/pluto-core/src/mcp/working.rs` (new), `mcp/mod.rs` (the `Host` method, `WorkChange`, the calls, `mod working;`), `mcp/tests.rs`, `src-tauri/src/mcp.rs` (the `WorkList`, `ShellHost::working`, the loop), the report, and the report.
- No other UI, no setting, no dependency.

## Must not
- Must not notify for chats that never sent `agent_resumed` (only Claude Code sends it today; Codex, Cursor and OpenCode will simply never get this notice — say so in the report and the docs).
- Must not change the waiting badge or A-1/A-4 behaviour.
- Must not store anything on disk.
- Must not run any timer when no chat is working.
- Must not show the chat's request text.

## Acceptance
1. A run notifies once at 25 min and once at 60 min and not otherwise; finishing, needing you, permission or error ends it; a second prompt restarts it from zero.
2. Two chats in different folders are tracked separately; the same assistant+folder is one run.
3. Runs older than 3 h vanish without a bubble.
4. The loop is not running when there are no runs (test the "should I tick" decision as a pure function).
5. Pure tests for all of the above and the exact texts; the existing `agent_resumed` tests still pass.
6. Unverified: real Claude Code `UserPromptSubmit` hook (the user must press Connect once to get it, as with A-1).
