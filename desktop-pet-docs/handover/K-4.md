# K-4 Make the timing-sensitive Rust tests deterministic

Some Rust tests pass alone but fail when the machine is busy, because they depend on real time. Known ones: `usage_collector::tests::a_film_or_a_call_with_no_input_keeps_counting`, and in `crates/pluto-core/src/mcp/tests.rs` the away/working tracker tests (`away_tracker_*`, `working_*`) when run with the whole suite.

## What to build
1. Reproduce: run `cargo test --workspace` several times under load (for example `stress` or running two suites at once) and list every test that fails at least once. Put the list in the report.
2. For each, remove the dependency on wall-clock timing: use the existing `Clock` trait (`crates/pluto-core/src/clock.rs`) or a fake clock, or `tokio::time::pause()` / `advance()` for tokio timers. Production behaviour must not change.
3. Where a test cannot be made deterministic without changing production code, change production code only to accept an injected clock (no behaviour change), and say so in the report.

## Acceptance
- `cargo test --workspace` passes 10 times in a row while another full suite runs in parallel (write the command you used in the report).
- No test is deleted, skipped, ignored or loosened (no bigger sleeps, no wider tolerances).

## Must not
No UI change, no new dependency, no change to what any test asserts.
